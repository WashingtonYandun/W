# ADR-006: Phase A identity, error composition and string ownership

Status: accepted for the PR #36 implementation; pending integration.

## Decisions

1. OptionalType(T) and the reserved Option[T] template intern to one optional TypeId. ResultType(T,E) and reserved Result[T,E] intern to one result TypeId. Nested optional constructors retain their depth. Builtin names and specialization namespaces cannot be redeclared by source programs.
2. Builtin constructors normalize at the compiler/runtime boundary. Result values use W_OK/W_ERR in C and WOk/WErr in Python. Some uses the canonical Option family; None uses W_NONE/WNone. Existing unboxed non-none optional payloads remain an ABI optimization/entry adapter for the supported W1 subset. Optional operations, matching, equality and display handle both layouts consistently. This revises the original implementation-guide preference to force every optional payload into a new wrapper; it avoids requiring the later W1 type-pipeline rewrite to preserve existing optional code.
3. Optional display is payload-transparent, including explicit Some. This intentionally changes the old `Option.Some(42)` display to `42`, matching `int?`. Some(None) remains distinct from None for equality and matching. An implicit conversion must not change optional nesting depth; use explicit Some to add a nullable layer. Dictionary queries wrap present values, including present None, so missing and present-null remain distinct.
4. Result success construction never flattens a nested Result. The checker marks success lifting when a return, binding, assignment, call argument or payload requires an outer Result. Bare T returns are success values even if T equals E; errors require Err. Type names do not select an error channel at runtime.
5. Parenthesized types are supported. Postfix optional binds tighter than right-associative `!`. Formatting preserves `(T ! E)?`, `(T ! E1) ! E2` and nested optional grouping. Each postfix propagation operator uses the checker-selected outer channel and requires a compatible enclosing return channel. There is no automatic E1-to-E2 conversion or implicit None-to-Err conversion.
6. Managed strings retain an immutable UTF-8 buffer, byte length and RC owner. Literals have static borrowed storage. Dynamic constructors take ownership; argv is copied. Concatenation, indexing, conversion, chr, slicing and file-read results enter registered owned temporaries. Enum/result construction consumes owned payloads. Dictionary get returns owned optional payloads. These contracts apply to the existing single-threaded runtime; no cycle collector or weak references are introduced.
7. HIR verification now includes recursive type components, typed patterns, lexical local/function resolution, direct call signatures, initializer/assignment/return compatibility, propagation channels and guard types, in addition to structural checks. It is a verifier for the current name-based HIR, not the later SymbolId-based representation.
8. Match guards execute after pattern bindings; failed guards continue to the next arm. Guarded arms do not establish unconditional coverage. Nested ADT/tuple payload products use a specialized pattern matrix to check exhaustiveness.

## Evidence and scope

`test_phase_a.py` records canonical identity, grouped-type roundtrip, negative channel/coverage/identity cases, interpreter/native parity and sanitized memory checks for strings, composed errors, domain-specific Err variants and guarded nested patterns. Linux CI enables LSan; macOS runs ASan/UBSan plus W_MEM_CHECK. W1 retains its declared generic-feature exclusion; this decision does not assert W1 generic parity.

No stable public C ABI is promised. Allocation failure, embedded-NUL string semantics, RC cycles, typed module sessions, generic ABI mangling and ownership optimizations remain separate concerns. The Phase A gates validate the contracts above and their recorded corpus; they are not a proof of memory safety for every possible program.
